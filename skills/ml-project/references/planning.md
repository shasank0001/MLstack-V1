# Plan work around observable decisions

Use when goals are sufficiently clear to choose a delivery path. Refer to an existing project brief or research state before making another plan. Keep a single `plan.md` when the user requests persistent tracking; do not create parallel experiment spreadsheets or shadow run registries.

Make each milestone produce a reviewable result: a working local command with captured evidence, a valid baseline, a bounded improvement test, or a reproducible report. Attach a concrete acceptance condition rather than an activity such as “investigate models.” Mark what is confirmed, proposed, blocked, complete, or unverified. Completion needs evidence, not an optimistic percentage.

Order dependencies by what could invalidate later work. An unknown target/split contract usually precedes a larger training run. A working documented command does not need an unrelated environment overhaul first. Prefer the smallest end-to-end demonstration over building every anticipated integration. Separate product plumbing, evaluation validity and scientific uncertainty so a successful tool test is not mistaken for a model improvement.

For the next experiment, state the question, controlled change, baseline, fixed evaluation, resource/time bound, required approval and the result that would change the next decision. Record unresolved implementation alternatives with a default or a cheap discriminator. Avoid treating every alternative as a user-blocking question.

In plan mode, save permitted named Markdown documents or freely organized research/**/*.md and create run proposals. Do not execute commands, perform computational EDA, modify training source, mutate preference/context memory, or install dependencies to make the plan more convincing. Document the needed act-mode check and its expected evidence instead. A route called experiment or optimize does not grant launch permission.

After approved work occurs, update statuses from actual results and retain important rejected approaches with their reason. Replanning is justified by new evidence or changed scope; rewriting the same plan after every tool read adds little. End with the next unresolved decision and a bounded action, not an autonomous backlog of sweeps.
