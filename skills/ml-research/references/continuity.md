# Resume from current evidence

Use when returning to a project or when prior attempts may affect the next decision. Use the refreshed preference/context snapshot and research index. Read the relevant brief/plan and research documents by the actual question; use memory search for deeper lasting preferences/context. Read linked runs when the decision depends on their measurements. Avoid treating all historical notes as current instructions.

Check whether recalled items are verified, superseded, stale, or contradicted by newer evidence. Distinguish a proposal from an executed run and an active job from a completed result. A proposed run can remain after a declined launch with no job. Check existing managed status before proposing a duplicate run; do not infer a live process from old logs or relaunch solely because a supervisor is missing.

Recover only the state needed to continue: current objective, accepted constraints, completed evidence, unsuccessful attempts and their reasons, active work, and the next unresolved decision. Unknowns remain unknown. Respect current user direction over stale plans. Do not search unrelated sessions or external services to reconstruct history.

Discuss mode reads and summarizes only. Plan mode can update host-allowed plans and freely organized research/**/*.md or create proposals, but cannot execute or mutate preferences. Keep research reasoning in ordinary Markdown; choose useful filenames and organization without enforcing headings or a fixed schema. Preserve evidence references and explain corrections. In act mode, use the memory tool only for lasting preferences/context. Do not create a second run registry or copy full metrics into preference memory.

Return a concise current-state summary and the bounded next action appropriate to the host mode. An old approval or a saved plan does not authorize a new launch, changed source, cloud job, or autonomous sweep.
